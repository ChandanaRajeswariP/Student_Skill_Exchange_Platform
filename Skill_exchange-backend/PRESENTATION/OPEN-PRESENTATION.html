Student Skill Exchange Platform

Backend: MySQL + MongoDB + Next.js APIs

MySQL stores structured student, skill and session records. MongoDB stores shared learning resources with embedded tags and flexible metadata. Both databases are used by the same backend.

Actual relational schema

PK means primary key. FK means foreign key. Multiple PK columns form a composite key.

students(id PK, name, email UNIQUE, password_hash, bio, department, created_at)
skills(id PK, name UNIQUE, category)
student_skills(student_id PK/FK, skill_id PK/FK, kind PK, level)
availability(id PK, student_id FK, day, start_hour, end_hour)
sessions(id PK, teacher_id FK, learner_id FK, skill_id FK,
         starts_at, ends_at, status, note, created_at)
reviews(id PK, session_id FK/UNIQUE, reviewer_id FK, rating, comment, created_at)
session_audit(id PK, session_id FK, old_status, new_status, changed_at)

Teacher and learner both reference students.id. All skill references point to skills.id. Reviews and audit records reference sessions.id. A session has at most one review.

student_skills.kind is offer or learn. Its three-column key allows one student to offer and learn the same skill. Availability additionally has a unique constraint on student, day, start and end.

MongoDB document model

{
  _id: ObjectId,
  ownerId: Number,   // students.id in MySQL
  skillId: Number,   // skills.id in MySQL
  title: String,
  summary: String,
  kind: 'article' | 'video' | 'exercise' | 'note',
  url: String,
  tags: [String],
  metadata: { difficulty?, durationMinutes?, pages?, language? },
  createdAt: Date,
  updatedAt: Date
}

Collection: learning_resources. Cross-database IDs are checked by the API; they are not SQL-enforced foreign keys. MongoDB validates document fields, builds a weighted text index and aggregates popular tags.
